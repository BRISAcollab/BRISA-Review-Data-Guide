BRISA REVIEW DATA GUIDE

Organize the project.
Share the evidence.

A practical structure for systematic review files, from day-to-day project management to a reusable public release.

Internal project structure Public release

Core principles

  • Software independent
  • Works with or without meta-analysis
  • Preserves original platform exports
  • Separates working files from final data
  • Documents methodological decisions
  • Publishes only what is useful and appropriate
01

Internal project

Preserves how the review was conducted over time: drafts, training, platform exports, reviewer decisions, adjudication, analysis files, and final materials.

02

Public release

A curated set of files that allows others to understand, assess, reproduce, and reuse the review. It does not need to reproduce the full internal history.

INTERNAL PROJECT

Recommended working structure

Use only the folders that are relevant to the project. The structure is independent of the software used at each stage.

PROJECT/
├── 00_README/
├── 01_ADMIN/
├── 02_PROTOCOL/
├── 03_SEARCH/
├── 04_SCREENING/
├── 05_EXTRACTION/
├── 06_ASSESSMENT/
├── 07_ANALYSIS/
├── 08_OUTPUTS/
├── 09_MANUSCRIPT/
└── 10_PUBLIC_RELEASE/
Software independent. Rayyan, Covidence, DistillerSR, spreadsheets, forms, RevMan, jamovi, R, Python, Stata, SPSS, and other tools can all fit this structure. Preserve the original export or project file whenever possible.

PUBLIC RELEASE

Repository-ready structure

The public release is assembled from the internal project. Omit modules that were not used.

PUBLIC_RELEASE/
├── README.md
├── dataset_description.json
├── LICENSE
├── protocol/
├── search/
├── screening/
├── extraction/
├── assessment/      # when applicable
├── analysis/        # when applicable
└── outputs/

PROJECT STAGES

What to keep at each stage

Each section separates the working record from the files normally considered for public sharing.

Protocol CORE

Internal

  • Protocol drafts
  • Final protocol
  • Registration record
  • Protocol amendments

Public release

  • Final protocol or persistent link
  • Registration information
  • Relevant amendments
Search CORE

Internal

  • Sentinel papers and search development
  • Draft and final search strategies
  • Original database exports
  • Deduplication files
  • Search log

Public release

  • Final strategies as executed
  • Search log
  • Deduplication method
  • Database exports when redistribution is permitted
Screening CORE

Internal

  • Screening guide
  • Training and calibration files
  • Original platform exports
  • Title/abstract decisions
  • Full-text decisions
  • Adjudication records
  • Final screening dataset
  • Full-text library

Public release

  • Screening guide
  • Final screening dataset
  • Full-text exclusion reasons
  • Reviewer-level decisions when useful
Extraction CORE

Internal

  • Extraction guide
  • Training and calibration files
  • Template or form
  • Original platform exports
  • Reviewer entries
  • Adjudication records
  • Final extracted dataset
  • Decision log

Public release

  • Extraction guide
  • Template or form
  • Final extracted dataset
  • Data dictionary or variable documentation
  • Relevant decision documentation
Assessment WHEN APPLICABLE

Internal

  • Assessment guide
  • Tool and version
  • Training files
  • Reviewer assessments
  • Adjudication
  • Final assessment dataset

Public release

  • Assessment guide
  • Tool identification and version
  • Final assessment dataset
  • Supporting judgement information when available
Analysis WHEN APPLICABLE

Internal

  • Input data
  • Analysis files or software project files
  • Derived datasets
  • Software environment information
  • Analysis outputs

Public release

  • Analysis-ready input data
  • Code or analysis project files
  • Derived data needed to reproduce results
  • Software and package versions when relevant
Outputs CORE

Internal

  • PRISMA flowchart
  • Figures
  • Tables
  • Supplementary materials

Public release

  • PRISMA flowchart
  • Reusable figures and tables
  • Relevant supplementary outputs

RATIONALE & SOURCES

Where the recommendations come from

Reporting guidelines inform what should be documented and shared. The folder layout itself is a BRISA working convention.

PRISMA 2020Availability of data, code, forms, and other review materials. PRISMA-SSearch strategies, information sources, dates, records, and search documentation. FAIR PrinciplesFindable, accessible, interoperable, and reusable research objects. BIDSInspiration for predictable structure, explicit conventions, metadata, and software-independent organization.
